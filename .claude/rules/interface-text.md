# Interface text and colours

- Every page loads `theme.js`, `i18n.js` and `lang.js` in `<head>`, after `style.css`, and links the manifest and `pwa.js` (`pwa.md`). A new page or page generator does the same.
- Link local CSS, JS and SVG files by plain relative paths (`style.css`, `../logo.svg#logo`). `tools/version_assets.py` adds `?v=<content hash>` to them in CI so browsers never mix a new page with an old cached file; do not add a query by hand.
- Lang Log offers the same languages as the profile site, in the same order (`LANGS` in `dist/lang.js`). Write interface text in English. All interface text lives in `i18n/<code>.yaml`, one file per language with the same keys: English in `i18n/en.yaml`, a value the page fills in as a placeholder (`{count}`, `{date}`, `{name}`). Add every new text to every file in the same pull request. `tools/build_i18n.py` (run by `tools/build_site.sh`) fails CI when a language lacks a key or uses a placeholder its English text lacks, and writes the dictionaries the pages load (`dist/i18n.js`, `dist/i18n/<code>.js`; not committed, never edited by hand).
- Never write a count or a limit into interface text (`generated-values.md` in `research-aide`): the script fills it in from the data or from the constant the code uses (`data.counts` in `dist/signs-and-scripts.js`, `SEARCH_LIMIT` in `dist/search.js`, the comments in `source-data/sources-and-scope.html` filled by `tools/build_home.py`), and the YAML text holds a placeholder for it.
- Numbers and dates captured by a pattern are written by `Intl` in each language's own style (`local()` in `dist/lang.js`); digits are 0-9 everywhere except Persian (۰-۹). Arabic and Persian pages get `dir="rtl"`, so use logical CSS properties (`inset-inline-end`, `margin-inline-start`, `text-align: start`) rather than left and right. Data (record names, source titles, citations, codes) is not translated; mark an element `notranslate` if its text could be mistaken for interface text.
- The term "languoid" stays in English ("Languoids") in every interface language (owner, 2026-11-07); its entry in each dictionary maps it to itself.
- Use only the colour variables at the top of `dist/style.css`. A new colour gets a `--c-<light hex>` variable with a light value and a dark value in both dark blocks.
- Keep the header as the brand on the left and one element on the right; the scripts put the theme toggle and the language menu after that element.
- Every record is a languoid in one tree (the owner's rule, 2026-11-07). Never show a record's kind (`level` or `kind`: family, subgroup, language, dialect, isolate, sample) as a label, badge, colour or legend in lists, trees, search results or record pages. Never offer a filter or toggle by kind either (the "Dialects" checkbox was removed, owner 2026-11-08). The data keeps `level` for sorting. `tools/build_site.sh` fails on kind labels, legends and the kind toggle.
- This covers what a page draws too, not only its words. Every record's map is built by the same steps (`map_html` in `tools/build_paths.py`: the deepest points on its branches, or its own point when none is below, all in one colour and size; the parent's other points as sisters). `tools/build_site.sh` fails if that code reads `level` or `kind`, or if `.lmap-main` and `.lmap-self` in `dist/record.css` get separate fills (owner, 2026-11-08: a family's page showed teal points and a language's page an orange one).
- Search has one results page, `dist/q.html` at `<site>/q?q=<terms>` (owner, 2026-11-08; GitHub Pages serves `q.html` at `/q`). It is a page of its own, never something `dist/404.html` turns into a search page, so nothing but the search page is ever drawn there. `dist/search.js` shows the results; the search boxes are GET forms to it, `dist/home.js` sends old top-page `?q=` links to it, and `dist/opensearch.xml` uses the same address. Keep `/?q=` links working.
- The top-level list on the top page is grouped by continent (owner, 2026-11-08): Africa, Eurasia, Oceania, North America, South America, in that order (`CONTINENTS` in `tools/build_home.py`, Oceania = Glottolog macroareas Papunesia and Australia). Each root appears once, under the continent where most of its languages are, counted from the data at build time; never assign one by hand. A continent is a heading only, never a node of the tree or a languoid.
