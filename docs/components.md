# UI components

Every piece of interface on Lang Log, by name, with the markup that marks it, the code that writes that markup and the directory that holds its look and behaviour (issue #89). Use these names in issues, pull requests and rule files. Before adding a component, look here for one that does the same job (`.claude/rules/ui-design.md`, "Reuse before adding"); a new or renamed component is added here in the same pull request.

## Where a component lives

Each component has its own directory (the owner's request, 2026-11-27), and pages only call it:

- `dist/components/<name>/<name>.css`: its look. Every page loads every component's stylesheet after `dist/style.css`, in the cascade order of `STYLES` in `tools/components/__init__.py` (`stylesheets()` writes the tags).
- `dist/components/<name>/<name>.js`: its behaviour, when it has a script. A page that shows the component loads it (`script()` writes the tag).
- `tools/components/<snake_name>.py`: the function that writes its markup, when the build writes it. Page generators (`tools/build_home.py`, `tools/build_paths.py`, `tools/info_page.py`) import it.
- `dist/style.css` keeps only the colour tokens, the fonts, the defaults of plain elements and the layout of the pages; `dist/record.css` and `dist/signs-and-scripts.css` keep what is only for their pages.
- `tools/check_components.py` (run by `tools/build_site.sh`) fails when a component directory holds other files, when `STYLES` and the directories disagree, or when a hand-written page does not load the stylesheets as `stylesheets()` writes them (`--write` fixes the pages).
